# BrokenBridge 점프 및 조기 추락 판정 문제

## 문제

- 화면에서는 충분히 점프한 것처럼 보이지만 다리 진입 순간 추락하는 경우가 있었다.
- 플레이어가 앞쪽에 있을 때 물 구간이 발에 닿기 전인데도 추락 판정이 발생했다.

## 원인

- 화면 출력은 정수 값인 `GetJumpScreenOffset()`을 사용하지만 기존 통과 판정은 부동소수점 `GetJumpHeight()`를 사용해 경계 결과가 달랐다.
- BrokenBridge는 원근 단계에 따라 물 행의 위치가 달라진다.
  - 가까운 표현: `obstacleY - 1`
  - 중간 표현: `obstacleY`
- 충돌 코드는 모든 거리에서 물 행을 `obstacleY - 1`로 계산해 중간 크기의 다리에서 한 줄 일찍 추락시켰다.

## 해결

- 다리 통과 높이를 화면 표현과 같은 `GetJumpScreenOffset() >= 3`으로 통일했다.
- 현재 거리와 이전 거리의 원근 단계를 각각 계산한다.
- `PolarObstacle::Draw()`와 같은 기준으로 실제 물 행을 구해 플레이어 발 행과 교차할 때만 추락시킨다.
- 충돌 로그에 `jumpHeight`와 `jumpOffset`을 함께 기록한다.

## 확인 항목

- [ ] 물 행이 발에 닿기 전에는 추락하지 않는지 확인
- [ ] 물 행이 발과 겹치면 추락하는지 확인
- [ ] 화면 기준 3칸 이상 점프하면 정상 통과하는지 확인
- [ ] 플레이어가 앞쪽·중앙·뒤쪽에 있을 때 판정 시점이 모두 자연스러운지 확인
- [ ] 높은 속도에서도 다리 판정을 건너뛰지 않는지 확인
## 추가 문제: 틈에 들어가기 전 추락

원근 투영 결과를 정수 화면 좌표로 바꾸면서, 물 행과 플레이어 발 진행선이 같은 행에 도달한 순간 화면에는 아직 한 칸의 여백이 남아 보일 수 있었다. 이 때문에 플레이어 입장에서는 다리에 들어가기 전에 추락한 것처럼 느껴졌다.

다리의 추락 판정선을 플레이어 발 진행선보다 화면 한 줄 아래로 조정했다. 장애물의 이전·현재 화면 위치를 비교하는 스윕 판정은 유지하므로 높은 속도에서도 다리를 통째로 건너뛰지는 않는다. 장애물을 검사 완료하는 시점도 같은 판정선을 사용하도록 맞췄다.

## 추가 문제: 충돌 후 다리가 아래에 보임

속도가 높으면 다리가 한 프레임에 여러 화면 행을 이동한다. 스윕 판정은 프레임 사이의 충돌을 올바르게 찾았지만, Crash 화면은 이동이 끝난 현재 좌표에서 멈추므로 다리가 펭귄 아래에 떨어져 보였다.

BrokenBridge 충돌이 확정되면 게임 판정 결과는 유지하면서 표시용 거리만 접촉 행으로 맞춘다. 따라서 Crash 화면에서도 물 틈과 펭귄 발이 실제 충돌 위치에서 만나며, 고속 이동을 놓치지 않는 스윕 판정도 그대로 유지된다.
## 밸런스 조정: 점프 허용 높이 완화

화면 높이 3칸 이상만 통과를 인정하면 다리 가까이에서 점프해야 하는 타이밍 범위가 지나치게 좁았다. 일반 BrokenBridge는 점프 높이가 화면 기준 2칸 이상이면 통과하도록 완화했다. 입력을 누르고 있는지만 확인하지 않고 실제 점프 높이를 사용하므로 기존 점프 유지 꼼수는 다시 생기지 않는다.

## 최종 판정: 공중 상태 기준

높이를 2칸으로 완화해도 점프 상승 직후나 착지 직전에는 화면 높이가 기준보다 낮아, 분명히 점프 중인데 추락하는 문제가 남았다. BrokenBridge는 높은 물체를 넘는 장애물이 아니라 바닥의 틈이므로 높이보다 공중 상태가 핵심이다.

최종적으로 `Player::IsJumping()`일 때 다리를 통과하도록 변경했다. 과거처럼 Space 키가 눌렸는지를 직접 검사하지 않으므로 키를 계속 누르는 것만으로는 통과할 수 없으며, `Player`의 고정된 점프 타이머 안에서만 안전하다.
